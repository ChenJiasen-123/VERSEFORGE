古典诗词演化入口（实验版）

使用方法
在项目根目录运行：
  python classical_agent.py --prompt "写七绝一首：远在战场之外的妻子思念已经战死的丈夫。至少一处有实际作用的用典。" --out runs/my-classical-poem
默认沿用本机旧项目 poetry-agent/.env 的服务配置，也可以用 --env-file 指定本地配置文件。
无需本地 GPU；实际生成会调用已配置的 DeepSeek 服务。配置文件不要放进生成记录。
每次新题、新配置使用新输出目录；相同目录只恢复完全相同的输入。

完整链路
原题 → 提取明示要求、识别体裁并选基本谱 → 从已核典源库选适用材料
→ 探索三条表达路径 → 审查构思 → 三份初稿 → 两代演化
→ 重读所有父稿与子稿 → 对称比较两个候选 → 独立重读原题并核对 → 返回作品及未决项。
原题入口0.3在末轮退稿后，可回选其他已审稿，最多核对三份不同正文；同一正文换标题或标点不能重问。

演化的单位是构思和完整作品：
每代保留父稿，产生两份针对薄弱处的变异稿、一份融合构思后整首重写的交叉稿。
按硬约束、题意、实际表达、用典作用和语言自然程度选三份进入下一代。
交叉不会剪贴父稿诗句，后代不会自动取代更好的父稿。
作者的构思声明不作为诗中已经表达的证据，独立审读只看原题、典源及正文。

审美原则
描写共同服务一种可感的体验、情感或思考；不要求每首有反转、金句或尖锐主题。
用典承担人物关系、处境或价值冲突，从而压缩背景，避免为展示学问堆叠名称。
保留对面落笔、移情、白描、复沓、留白等路径的选择；手法不能代替表达。

边界与降级
总预算覆盖审题、选典、演化和复核，默认最多45次调用、900秒；停止发起新调用不代表立即中断在途请求。
新的一次审读异常时，仅可保留同一原题、典源及完整正文此前已核过的意见，并记录终审未完成。
正文变动后不能沿用旧审读。原题要求未确认时返回 needs_review，不冒充已合格。
有基本谱读音未决的稿标记 candidate_with_unresolved_readings，不能称作全谱通过。
模型评价仍是代理判断，代码与数据审计不能认证文学质量。
解释原题时区分范围限制与逐项覆盖；结合原题语境辨认人物关系，不强制诗句重复身份标签。

实验记录
experiments/classical_evolution/：冻结的演化核心、试题、典源与首轮方案。
classical_agent.py：原题自动入口，另有审读异常回退及既有审美知识接入；与冻结核心分版本记录。
runs/classical-evolution-held-01：十二道题各两次，新核心与旧默认流程共48次。
runs/classical-evolution-multicandidate-control-01：追加旧三候选流程的24次对照；引用已有24次新核心结果，不重复生成。
runs/classical-evolution-raw-pilot-01：完整原题入口四题验证。
runs/classical-evolution-raw-pilot-02：0.3版修正后的四题验证，结果与第一版分开保留。
最终报告必须同时保留失败、待核读音、全部样本分母、调用量与耗时，不以几首最好作品代替稳定性。
