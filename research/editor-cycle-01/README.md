# 审稿—修订—复核—双序比较实测01

实验脚本：tmp/editor_cycle.py。使用修正后的独立审稿指令，完整请求响应保存在对应JSON中。所有调用是相同基础模型的独立上下文，不是不同模型共识。实验没有修改网页正式生成流程。

《退回的信》：审稿由前轮keep变为revise，实际修订补出了寄语，随后完成题意核对、修订稿文学审读与两个顺序的比较。两个比较顺序均偏向修订稿，但adopt_revision为false。规则是题意确认、修订稿审读keep以及双序一致偏向新稿缺一不可；本轮不宣称新稿已达到文学要求。原稿与所有中间证据完整保留，未发布为最终作品。

《门背后》对照：审稿仍对我／你时间关系提出质疑，并提到“收件人是否缺席”，不能证明前轮误判已消除。响应中的text_sound缺少basis，触发invalid_sound_basis，未执行修订。完整原响应已保存，可定位这次失败；没有自动重复调用直到出现理想结果。

结论：链路能保留未获充分认可的旧稿，但审读仍可能过度解释或提交无效结构。双序比较一致不是独立文学质量证明。实验仅涉及两篇已见稿，不支持跨题材或总体生成水平的结论。

下一步应将独立审稿的语义问题、响应协议失败分别处理；增加未见题材与合理非写实作品，比较是否出现过度修正。程序测试通过不能替代此类实测。
