# 实际内容核对与局部修订

用户要求把《退回的信》的评阅落实到 Agent。新增流程：拆分实际内容要求；分别引用人的寄语与系统回复；发现只有泛指、收件人字段或旁观式自问时标记待确认，并触发至多一次局部修订；对最终文本重新核对。

本目录 result.json 保存用户原稿、真实 API 核对、修订输入、修订文本及复核。revision.md 是该次模型修订，未做人工作品润色。原稿未通过要求核对，修订为21行并通过本次核对。规则不强制原话使用引号，也不把题干举例变成必用素材。

局限：本次模型补出了寄语，调整了“正文只有编号”，但没有充分交代纸信与屏幕的切换，关屏后回复再次出现也仍需编辑判断。通过题意核对不代表叙事衔接、文学质量已通过；衔接要求目前属于创作及修订指令，尚无独立可靠的自动证明。本次是提示与工作流改进，没有训练 API 模型参数。

验证：188项单元及本地 HTTP 测试通过；另以用户原诗完成三次真实 API 调用（核对、修订、复核）。自动研究目标保持暂停。
